# ADR 0003 — โครง URL สำหรับหลายภาษา

- **สถานะ:** ยอมรับแล้ว (⚠️ เจ้าของโปรเจกต์ยังไม่ได้ยืนยัน — agent ตัดสินใจแทนภายใต้สมมติฐาน)
- **วันที่:** 22 ส.ค. 2026

## บริบท

โจทย์บอกว่า "ไทยเป็นหลัก แต่ตั้งแต่วันแรกต้องวางโครง i18n รองรับ en"

นี่เป็นการตัดสินใจที่ **ย้อนกลับยากที่สุดในโปรเจกต์** เพราะเมื่อ Google index URL ชุดหนึ่งไปแล้ว
การเปลี่ยนโครง URL หมายถึงต้อง 301 ทุกหน้า และเสีย ranking ชั่วคราวเสมอ
สำหรับเว็บที่พึ่ง SEO เป็นช่องทางเดียว ความเสียหายนี้ใหญ่กว่าปกติมาก

จึงต้องเลือกให้ถูกตั้งแต่ก่อนหน้าแรกขึ้น production (1 ก.ย.) ไม่ใช่ตอนจะทำ en จริง (หลัง 19 ต.ค.)

## ทางเลือก

| แบบ | หน้าตา | ข้อดี | ข้อเสีย |
| --- | --- | --- | --- |
| **A. ไทยไม่มี prefix + `/en`** | `/qr/promptpay`, `/en/qr/promptpay` | URL ไทยสั้น อ่านง่าย แชร์สวย · ไม่ต้อง redirect ที่ root · ตรงกับที่ตลาดหลักคือไทย | ถ้าโตเป็น global ทีหลัง โครงจะดูไม่สมมาตร |
| B. `/th` + `/en` ทั้งคู่ | `/th/qr/promptpay` | สมมาตร ขยาย locale ที่ 3–4 ง่าย | หน้าไทย (ตลาดหลัก) ต้องแบก prefix โดยไม่จำเป็น · root ต้อง redirect ซึ่งเสีย link equity นิดหน่อย · URL ยาวขึ้นทุกหน้า |
| C. ไทยล้วน ไม่ทำ i18n | `/qr/promptpay` | scope เล็กสุด เร็วสุด | ถ้าเติม en ทีหลังต้องแก้ routing ทั้งเว็บ = สิ่งที่ ADR นี้พยายามเลี่ยง |

## การตัดสินใจ

**เลือกแบบ A** — ไทยไม่มี prefix, `/en` สำหรับอังกฤษ

เหตุผล: ตลาดหลักคือไทยและจะเป็นแบบนั้นไปอีกนาน หน้าที่ต้อง rank คือหน้าไทย
การให้หน้าที่สำคัญที่สุดมี URL สั้นและสะอาดที่สุดคือการจัดลำดับที่ถูก
ส่วนข้อเสียเรื่องความไม่สมมาตรเป็นความรู้สึกเชิงสถาปัตยกรรม ไม่ใช่ต้นทุนจริง

## สิ่งที่ต้องทำตั้งแต่วันนี้ (แม้ยังไม่มี en)

1. `hreflang` — ทุกหน้าประกาศ `th` และ `x-default` ตั้งแต่แรก เพิ่ม `en` เมื่อมีหน้าจริง
2. `<html lang="th">` — ตั้งแล้วใน `src/app/layout.tsx`
3. **ห้าม hardcode ข้อความไทยที่ต้องแปลลงใน component โดยตรง**
   ให้อยู่ในไฟล์ที่ดึงออกมาเป็น message catalog ได้ทีหลัง
4. `siteConfig.supportedLanguages` ใน `src/lib/site.ts` เป็นแหล่งความจริงเดียว
5. **ยังไม่ติดตั้ง `next-intl` หรือไลบรารี i18n ใด ๆ** — เพิ่ม dependency ที่ยังไม่ใช้
   คือต้นทุนที่ไม่ได้ประโยชน์ เลือกไลบรารีตอนจะทำ en จริง โดยเขียน ADR แยก

## ผลที่ตามมา

- หน้าไทยทั้งหมดอยู่ที่ root ตามที่ต้องการ
- ถ้าวันหนึ่งต้องเปลี่ยนเป็นแบบ B จะต้อง 301 ทุกหน้า — **ยอมรับความเสี่ยงนี้**
  โดยแลกกับ URL ไทยที่ดีกว่าตลอด 1–2 ปีแรกซึ่งเป็นช่วงที่สำคัญที่สุด
- ⚠️ ถ้าเจ้าของโปรเจกต์ไม่เห็นด้วย **ต้องบอกก่อน 1 ก.ย.** (วันที่หน้าแรกขึ้น production)
  หลังจากนั้นการเปลี่ยนจะมีต้นทุน SEO จริง
