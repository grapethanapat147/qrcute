# ADR 0007 — เลือก payment gateway

- **สถานะ:** ✅ ตัดสินใจแล้ว — **Opn Payments (Omise)** จดในนามบุคคลธรรมดา
- **วันที่:** 7 ก.ย. 2026 (เสนอ) · 7 ก.ย. 2026 (อนุมัติ)

## 🔴 ข้อค้นพบที่เปลี่ยนโจทย์ก่อนจะเลือกเจ้าไหน

**พร้อมเพย์ตัดเงินอัตโนมัติซ้ำไม่ได้** — เป็นการจ่ายครั้งเดียวเสมอ
การตัดเงินอัตโนมัติรายเดือนทำได้เฉพาะ**บัตรเครดิต/เดบิต**เท่านั้น
([เอกสาร Omise](https://docs.omise.co/how-to-do-recurring-payments))

เอามารวมกับสมมติฐานใน [strategy.md](../strategy.md) ที่ว่า SME ไทยจำนวนมากไม่ชอบ subscription
และหลายรายไม่มีบัตรเครดิตด้วยซ้ำ จะได้ภาพนี้:

| ช่องทาง | รายเดือน/รายปี | จ่ายครั้งเดียว (Lifetime) |
| --- | :--: | :--: |
| บัตรเครดิต/เดบิต | ✅ | ✅ |
| **พร้อมเพย์** | ❌ | ✅ |

**แปลว่า Lifetime pack ไม่ใช่แค่ "ทางเลือกให้คนไม่ชอบ subscription" อีกต่อไป
แต่เป็น *ช่องทางเดียว* ที่ลูกค้าไทยที่ไม่มีบัตรเครดิตจะจ่ายเงินให้เราได้**

ถ้าลูกค้ากลุ่มนี้เป็นสัดส่วนใหญ่จริงตามที่ strategy.md เดาไว้ รายได้ส่วนใหญ่จะมาทาง
พร้อมเพย์แบบจ่ายขาด → **ค่าธรรมเนียมพร้อมเพย์สำคัญกว่าค่าธรรมเนียมบัตร**
ซึ่งกลับด้านกับที่ SaaS ทั่วไปคิดกัน

> ⚠️ ตัวเลขทั้งหมดมาจากหน้าเว็บสาธารณะและบทความเปรียบเทียบ **ยังไม่ได้ยืนยันกับผู้ให้บริการ**
> ต้องขอใบเสนอราคาจริงก่อนตัดสินใจ — อัตราจริงมักต่อรองได้และเปลี่ยนตามประเภทธุรกิจ

| **ค่าธรรมเนียมพร้อมเพย์** | 1.65% | **0.80%** | ตามแพ็กเกจ | ต่อรอง | 1.65% |
| ตัดเงินซ้ำอัตโนมัติ | ✅ Schedule API | ✅ | ต้องตรวจสอบ | ✅ | ✅ |
| เอกสาร/API | **ดีที่สุด มี rate card สาธารณะ** | ดี | พอใช้ | ต้องคุยก่อน | ดีมาก |
| ค่าแรกเข้า | ไม่มี | ไม่มี | ไม่มี | ต่อรอง | ไม่มี |

| รายการ | ราคา | ค่าธรรมเนียม Opn | ค่าธรรมเนียม Xendit | ต่างกัน |
| --- | --- | --- | --- | --- |

ส่วนที่ยอดใหญ่อย่าง Lifetime พร้อมเพย์ Xendit ถูกกว่าชัดเจน

## ข้อเสนอ: **Opn Payments (Omise)**

**เหตุผลหลักคือความเสี่ยงของการ integrate ไม่ใช่ค่าธรรมเนียม**

1. **เป็นเจ้าเดียวที่เปิด rate card และเอกสาร API ครบเป็นสาธารณะ** — เจ้าอื่นต้องคุยกับ
   ฝ่ายขายก่อนถึงจะรู้ว่าทำอะไรได้บ้าง ซึ่งกินเวลาที่เราไม่มี (เหลือ 4 สัปดาห์ถึง deadline)
2. **มี Schedule API สำหรับตัดเงินซ้ำ** ที่มีเอกสารชัด ไม่ต้องเขียน scheduler เอง
3. **ค่าธรรมเนียมถูกที่สุดสำหรับ Pro รายเดือน** ซึ่งเป็นสินค้าที่เราอยากให้โตที่สุดในระยะยาว
4. เป็นบริษัทไทย มี support ภาษาไทย — สำคัญเมื่อเจอปัญหาเรื่องการโอนเงินเข้าบัญชี

**สิ่งที่ยอมแลก:** ค่าธรรมเนียมพร้อมเพย์แพงกว่า Xendit เท่าตัว (1.65% vs 0.80%)
ถ้า Lifetime ขายดีจริงตามที่คาด ที่ยอดขาย 100 ชิ้น/เดือน จะต่างกันราว 3,300 ฿/เดือน
→ **คุ้มที่จะกลับมาทบทวนเมื่อยอดถึงระดับนั้น** ไม่ใช่ตอนนี้

เพราะ entitlement layer แยกจาก gateway อยู่แล้ว ([prd.md](../prd.md) §5.1) การย้ายเจ้าทีหลัง
กระทบแค่ชั้น adapter ไม่กระทบตรรกะสิทธิ์และไม่กระทบข้อมูลลูกค้าเดิม

## 🔴 สิ่งที่อยู่บนเส้นทางวิกฤต — ต้องเริ่มวันนี้

**การสมัคร gateway ใช้เวลาอนุมัติเป็นวันถึงสัปดาห์ และต้องใช้เอกสาร**

ทุกเจ้าในตารางต้องยืนยันตัวตนธุรกิจ โดยทั่วไปต้องมี:

- หนังสือรับรองบริษัท หรือทะเบียนพาณิชย์ (บุคคลธรรมดาสมัครได้ไหมต้องถามเป็นราย ๆ)
- บัญชีธนาคารในชื่อธุรกิจ
- เว็บไซต์ที่ใช้งานได้จริง พร้อมหน้าเงื่อนไขการใช้งานและนโยบายคืนเงิน

> ⚠️ **ข้อสุดท้ายผูกกับงานอื่น** — ต้องมีเว็บ live พร้อมหน้า ToS และนโยบายคืนเงินก่อน
> ซึ่งแปลว่าเรื่องโดเมนที่ค้างมาตั้งแต่ 25 ส.ค. บล็อกการสมัคร gateway อยู่ด้วย

**Milestone "เก็บเงินได้จริง 6 ต.ค." จะพลาดถ้าไม่เริ่มสมัครภายในสัปดาห์นี้**
ไม่ว่าโค้ดจะเสร็จเร็วแค่ไหนก็ตาม

## ทางเลือกที่ไม่เลือก และเหตุผล

| ทางเลือก | ทำไมไม่เลือก |
| --- | --- |
| Xendit | ถูกกว่าที่พร้อมเพย์ แต่ค่าคงที่ ฿10 ทำร้าย Pro รายเดือน และเอกสารฝั่งไทยน้อยกว่า |
| GB Prime Pay | MDR ถูกที่สุด แต่ยังไม่ชัดเรื่อง recurring และเอกสาร API บางกว่า — เสี่ยงเกินไปกับเวลาที่เหลือ |
| 2C2P | ต้องคุยฝ่ายขายก่อนถึงจะเริ่มได้ ไม่เหมาะกับคนเดียวที่มีเวลา 4 สัปดาห์ |
| Stripe | DX ดีที่สุด แต่ค่าธรรมเนียมไม่ได้ถูกกว่า และ SME ไทยคุ้นกับชื่อไทยมากกว่า |
| รับโอนพร้อมเพย์เองแล้วเช็คสลิปด้วยมือ | ทำได้ตอนลูกค้า 5 ราย แต่พังทันทีที่ 50 ราย และเราขาย "QR ที่ถูกต้อง" จะมาทำระบบเงินแบบลวก ๆ ไม่ได้ |

## สิ่งที่ตัดสินใจ

**ใช้ Opn Payments (Omise) จดในนามบุคคลธรรมดา**

เอกสารที่ Opn ขอสำหรับบุคคลธรรมดา: รูปถ่ายตัวเองถือบัตรประชาชน
และหน้าแรกของสมุดบัญชีธนาคารที่ชื่อตรงกับบัตร

## ผลที่ตามมาในโค้ด

1. **สิทธิ์ของผู้ใช้ต้องไม่รู้จักชื่อ Opn** — `src/lib/billing/entitlements.ts`
   มี test ที่อ่านซอร์สตัวเองแล้วยืนยันว่าไม่มีชื่อผู้ให้บริการโผล่ในไฟล์
   ตัวแปลงเหตุการณ์เฉพาะเจ้าอยู่ใน `src/lib/billing/opn/` แยกออกมาต่างหาก
2. **ตารางฝั่ง billing เก็บชื่อ gateway เป็นคอลัมน์ ไม่ใช่ชื่อตาราง**
   (`webhook_events.gateway`, `payments.gateway`) ย้ายเจ้าได้โดยไม่ต้อง migrate ของเก่า
3. **ยังขายได้เฉพาะรายการที่เก็บเงินครั้งเดียว** — `RECURRING_EVENTS_SUPPORTED = false`
   เพราะเอกสารสาธารณะไม่ได้ระบุชื่อเหตุการณ์ของการต่ออายุ (ตระกูล `schedule.*`) ครบ
   ต้องเห็นเหตุการณ์จริงในแดชบอร์ดก่อนถึงจะเปิด ห้ามเดา

## 🔴 ข้อจำกัดที่ต้องออกแบบรอบตัวมัน: ไม่มีการยิงซ้ำ

> "Omise does not currently guarantee automatic retries for failed deliveries"
> — [เอกสาร Omise](https://docs.omise.co/api-webhooks)

แปลว่าถ้าเซิร์ฟเวอร์เราล่มตอนที่เขายิงมา **เงินเข้าแล้วแต่สิทธิ์ไม่เปิด และไม่มีใครรู้**
ลูกค้าจะเจอว่าจ่ายแล้วใช้ไม่ได้ ซึ่งเป็นความเสียหายที่แก้ทีหลังแพงมาก

จึงต้องมีงานกระทบยอดที่ดึง `GET /events` มาเทียบกับตาราง `webhook_events`
ว่ามีเหตุการณ์ไหนหล่นหาย — `bun run reconcile:opn` (ดู `scripts/reconcile-opn.ts`)
**งานนี้ไม่ใช่ของแถม แต่เป็นส่วนหนึ่งของความถูกต้องของระบบเงิน**

## สิ่งที่ยังต้องทำฝั่งคุณ

1. **สมัคร Opn ทันที** ไม่ต้องรอโค้ดเสร็จ — ต้องมีเว็บที่เข้าถึงได้จริง
   พร้อมหน้าเงื่อนไขการใช้งานและนโยบายการคืนเงิน
2. **ซื้อโดเมน** — ยังบล็อกทั้งการสมัคร gateway และความยาว shortcode อยู่
3. ตั้งค่า webhook endpoint ในแดชบอร์ดเป็น `https://<โดเมน>/api/webhooks/opn`
   แล้วเอา secret มาใส่ `OPN_WEBHOOK_SECRET`
